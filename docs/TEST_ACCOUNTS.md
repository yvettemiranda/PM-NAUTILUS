# TEST 多账户

TEST 支持固定的 1—10 号模拟账户。每个账户使用同一套策略和模拟成交规则，可分别设置参数和初始资金，并独立启动、暂停和重置。页面顶部的账户选择器只切换查看及操作的对象，不会启动或暂停任何账户；其他账户在后台继续运行。

## 账本与初始值

- 1 号继续使用原来的 `TEST/state.sqlite`，不搬迁、复制、清空或重置原账本。
- 2—10 号分别使用 `TEST/accounts/2/state.sqlite` 至 `TEST/accounts/10/state.sqlite`。
- 新账户首次建立时复制 1 号当时保存的策略参数和初始资金设置，不复制余额、持仓、订单、成交、收益曲线或交易历史。首次建立后，各账户参数不再互相同步。
- 每个账户分别保存订单、成交、持仓、收益采样、策略状态及模拟盘口消耗。市场元数据在各账本中保留所需快照，保证历史展示与重放。
- 所有路径均相对于 `PM_DATA_DIR`，位于现有持久化数据卷内。

公共市场发现和行情连接由现有 `PublicMarketHub` 共享，订阅覆盖所有账户所需市场的并集。共享的只是外部真实价量，各账户使用自己的模拟盘口与消耗记录。一个账户成交不会占用另一个账户的模拟流动性。

## 启停、资金与重置

进程重启后，十个账户均恢复参数与历史，并进入 PAUSED；不会自动恢复新增买入。PAUSE 沿用原含义：停止新买并取消未完成买单，已有持仓的目标卖出、止损和结算仍继续处理。

初始资金只在该账户暂停且没有交易历史时可修改。已有历史若需要重新设置本金，应先明确执行该账户的重置；重置会清空该账户的模拟历史并恢复原有默认设置，其他账户不受影响。重置保留双重确认，确认文字明确标注账户号。

## API 兼容

现有 TEST 接口使用 `account_id=1` 至 `account_id=10` 指定账户。省略时固定指向 1 号，保持原有脚本兼容。账户号通过整数白名单解析，不接受数据库路径。

账户参数适用于 dashboard、preferences、start、pause、reset、trade-records、validation 和 performance。账户选择只存在于浏览器中，服务端没有全局“当前账户”；不同浏览器或标签页可查看不同账户。前端将请求与发起时的模式、账户和视图代次绑定，迟到响应不能覆盖另一个账户；记录游标、持仓快照和曲线也分别隔离。

LIVE 继续使用 `LIVE/state.sqlite` 和原有钱包、账本、交易及运行机制。TEST 账户参数不进入 LIVE 钱包接口或执行逻辑。

## 运维与验收

后台健康检查需覆盖全部 TEST 账户并标注错误来源；原有默认 TEST 状态字段继续代表 1 号。元数据维护分别使用各账户自己的业务引用与清理游标。磁盘保护仍是整个数据目录的统一保护，不自动删除模拟账本、交易历史或钱包。

账户的资金、订单、策略状态和操作相互独立；服务器进程、CPU、内存、磁盘和公共行情源仍然共享。公共断网、进程退出、磁盘不足会影响多个账户，验收应包含十账户同时消费行情与 HTTP 响应的负载检查。

上线前后应核对：原账户完整数据及 generation 保留；新增账户为空白交易账本；单账户改参数、启停、成交和重置不影响其他账户；快速切换不串数据；重启均暂停；LIVE 专用模块和数据保持原状。数据备份应使用一致性 SQLite 备份或停止写入后的完整快照，不能只复制正在写入的主数据库而遗漏 WAL。
