# 从 GitHub 到首次实盘

这份说明适用于换电脑、换服务器，愿意丢弃旧 **TEST 模拟交易记录**，并且本程序还没有真实 LIVE 订单、持仓或待结算权利的情况。已经用本程序做过实盘时，请看下文“以后换服务器”；真实账本不能丢。

**当前版本尚不能把下面的第 5 步当成可直接执行的实盘开关。**2026-10-07 的[逐环节审计](END_TO_END_HANDOFF_2026-10-07.md)发现每轮金额不一定包含实盘手续费、实盘份额/费用记账可能与交易所不同，以及新钱包缺少网页赎回授权流程。先修复并重新验收这些环节，再使用下述操作顺序。当前服务器的交易出口还被 Polymarket 标为限制新开仓地区。

## 你需要准备什么

- 一台允许 Polymarket API 新开仓的服务器。初次安装仍需请 Codex 或管理员配置 Docker、网页 HTTPS 和登录密码；完成后，日常钱包操作在程序网页的 **LIVE** 页进行，不必每次进服务器。
- 自己钱包的 **12 个助记词或私钥**，以及 Polymarket 显示的**公开资金钱包地址**。保存后网页会显示由助记词或私钥得出的签名地址，请在启用前亲自核对。若是别的助记词长度、硬件钱包或本程序不支持的钱包类型，先不要尝试导入。
- 一个你能长期保存的**解锁密码**，至少 12 个字符。它用于解锁服务器上的加密钱包文件，和网页登录密码是两回事。丢失后程序无法替你找回钱包秘密；还需要保管好钱包原有恢复方式。

不要把助记词、私钥、解锁密码发到聊天、GitHub、截图或普通笔记。输入位置只有你通过 **HTTPS 打开的本程序 LIVE 钱包页面**。这套方式会把你输入的助记词或私钥经 HTTPS 交给服务器处理：助记词只用来派生签名密钥，磁盘只保存加密钱包文件；LIVE 解锁后，服务器进程在内存中持有签名密钥以便交易。网页方案并不意味着密钥永远只留在你的电脑。

## 将来最简单的操作顺序

1. **请人完成一次服务器安装。**让 Codex 或管理员从 [GitHub 仓库](https://github.com/yvettemiranda/PM-NAUTILUS)取得经验证的版本，按[部署手册](DEPLOY.md)配置 Docker、HTTPS 与网页登录。安装者先确认公开的 [交易规则文件](../config/strategy-profile.json) 仍是你要用的版本，并在首次启动前把规则应用到空白 TEST、LIVE 两套账本。安装完成应先显示 `TEST / PAUSED`，LIVE 钱包未接入。
2. **打开网页，先看规则。**登录后可继续使用 TEST；切到 LIVE 只是查看实盘页，不会下单。点击右上角齿轮，网页会展开并定位到交易设置；在 LIVE 页核对每轮金额、筛选、目标卖出和止损，和 TEST 分别核对。两套规则各自保存，TEST 中改动不会自动复制到 LIVE。沿用已有规则，不另加首轮总投入、单笔金额或试单次数限制。
3. **在 LIVE 页接钱包。**选择“12 词”或“私钥”，只在网页表单输入一次，并填写公开资金钱包地址，自己设置解锁密码。提交后网页会显示签名地址和资金地址；启用前请亲自核对。程序会把钱包信息加密保存在服务器 `/data/wallet/live.vault`；不会把助记词原文写入文件，也不会把私钥、密码上传 GitHub。首次导入后不能靠“重新导入另一个钱包”覆盖已经产生真实交易的账本。
   如果导入后发现接错、当前 LIVE 未启用且没有交易记录，可在同一页“钱包备份与管理”输入解锁密码清除空白钱包，再重新输入；已有实盘交易记录时不能用这个入口删除。
4. **运行只读核对。**网页检查服务器地区、钱包类型、资金和手续费余额、部分交易所授权、原有挂单与持仓，以及它是否与 LIVE 账本属于同一账户。核对阶段不会下单或取消旧订单。当前核对未覆盖赎回所需的 CTF 适配器授权，也不能证明实盘手续费、成交和结算会符合 TEST；请按审计文档先完成修复与验收。钱包以前手工开的仓位不会自动变成本程序的仓位。
5. **修复和实盘验收完成后，才确认启用并自己按 START。**在 LIVE 页确认启用后，状态先是 `LIVE / PAUSED`；这时仍没有自动开始新买。再由你按 **▶ START**，程序才按现有规则发出真实交易。PAUSE 会停止新买；已有本程序持仓的卖出、止损和结算仍可能继续。

服务器重启后，打开网页在 LIVE 页输入解锁密码，再重新核对并启用；不会自动恢复 RUNNING。**LIVE 未解锁期间，本程序不会管理已有 LIVE 持仓。**请看页面的锁定和账户状态，不能把暂时没有显示的持仓理解为已经清仓。TEST 不需要钱包，仍可独立运行。

2026-10-06 当前服务器从自身网络出口请求 Polymarket 地区接口，结果为 `blocked=true`、`US/CA`。按 [Polymarket 官方地区规则](https://docs.polymarket.com/api-reference/geoblock)，该出口不能用于 API 新开仓；网页地区检查会阻止 LIVE 启用。将来换服务器后，必须从新服务器自己的网络出口重新核对。

## GitHub 能恢复什么

GitHub 有程序、说明和你同意公开的 `config/strategy-profile.json`。它**没有**服务器钱包、解锁密码、真实交易记录或最新账本。公开规则文件也不会随着你在网页改参数而自动更新；以后换服务器前要确认它仍是你想用的规则。

旧 TEST 模拟交易可按你的选择丢弃。**第一次实盘以后，LIVE 账本就不能随便丢。**它记录程序自己的订单、持仓和待结算权利；只下载 GitHub 后从空白 LIVE 启动，程序无法可靠识别这些历史。LIVE 页的 `.pmnb` 是下载时的加密快照，可作日常备份，但当前程序在 PAUSE 后仍可能继续卖出或赎回，所以它不能自动作为最后一份迁移备份。换服务器时由管理员停止旧实例、制作最终一致性加密备份，再在新服务器恢复并核对；不能让两台服务器同时管理同一钱包。备份和恢复细节见[部署手册](DEPLOY.md)。
