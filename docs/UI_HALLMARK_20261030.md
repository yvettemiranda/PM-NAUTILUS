# Hallmark 界面更新

本轮使用 Hallmark 2.0 的应用界面规范改进 PM-NAUTILUS 的视觉和排版。沿用现有浅色、青绿品牌色、原信息和操作入口，改动的程序文件仅为 `web/index.html` 与 `web/styles.css`。实际应用 SHA、CI 与服务器验收以 [HANDOFF](../HANDOFF.md)和 [VALIDATION](VALIDATION.md)为准；源码出现新样式不代表服务器已自动更新。

## 视觉变化

- 模式与账户序号合为一组，保留原生 1—10 号选择器；运行状态保留文字，启停和配置使用统一的图标、边界和焦点样式。
- 桌面将累计盈亏、总资产估算和现金放在同一视线；手机保留分行。收益曲线仍默认七天，可拖动、切换时／日及回到最新，完整历史不变。
- 字号、灰字对比度、间距及按钮状态统一；配置说明及单位不再使用 9—10px 小字，手机数字输入使用 16px。
- 持仓和市场列表提供展开指示，保留原有策略详情、记录、状态、风险提示及全部钱包字段。较长标题与金额可以换行，不通过缩写或截断减少金额精度。

没有增加前端框架、字体下载、图片服务、统计请求或外部 UI 服务。图标由本地 CSS／SVG 提供，不引入运行依赖，不按服务器型号分支。Hallmark 安装在开发机的技能目录，生产程序不运行 Hallmark。

## 行为保留

`app.js`、全部 Python、配置、依赖和测试文件与前版字节一致。143 个原静态 ID、30 个原输入字段及其既有属性、脚本入口全部保留，按钮 handler 与接口调用不变。只改装饰性图标、样式入口版本、分组标记和辅助语义；数值、策略公式、警示及钱包文字继续沿用原内容。

本轮不迁移或重置数据库，不改参数、资金、订单、持仓、收益采样、模拟成交及真实执行逻辑，不启用 LIVE 或操作真实资金。页面显示优化不构成实盘闭环验收。

## 检查范围

本地 1,256 项程序回归、122 项页面回归通过；Ruff check、145 文件格式、JavaScript 语法与 diff 检查通过。浏览器另核对 10 号空账户、返回 1 号、记录 20→40 条、持仓及策略展开、配置表单和未启用 LIVE 的钱包界面。没有点击启动、重置、保存参数或任何钱包提交操作。

Hallmark 静态检查及原内容／绑定核对通过，Floor 0 FAIL、Reflex 0、未处理 WARN 0；统一表单控件的 F7 已说明理由，原始范围分隔符按原文保留。Hallmark 自带的字段提取只记录到一个字段，因此另用完整 HTML 解析核对全部 143 个 ID 和 30 个输入，不把前者误报成全量绑定证明。

宿主要求浏览器交互统一通过 Cua，因此实际渲染、响应式与截图由真实 Chrome／Cua 完成，未执行或声称通过 Hallmark 的 Puppeteer 渲染器。320、360、390、768、1024、1280、1440、1920 八种宽度无横向溢出，顶栏操作均在屏内，SVG 保持原 200px 高度并匹配 viewBox。独立审阅完整桌面与手机截图，结论为 ship。

预览采用独立临时 TEST 账本和受控原生模拟成交／报价，展示数据明确为模拟数据，不是服务器账户成绩。实际账户、配置、资金和历史不用于设计造数。本应用 `8ab1937e84b1f63db3db46a07eca8a4d17876a58` 已通过 [双架构 CI 41040472149](https://github.com/yvettemiranda/PM-NAUTILUS/actions/runs/41040472149)并部署服务器，完整验收见下文。

## 发布与服务器核对

固定镜像发布前完成十账户当前副本、停机冻结副本验证及 11 份账本一致性备份；上线后核对全部 TEST 的参数、初始资金设置、generation、原订单和历史前缀，以及历史／收益接口和分批上限。LIVE 账本精确一致，钱包、模式意图、受保护环境和 Compose／容器配置未变；五个网页资源哈希与固定源码一致。
