# TEST 通用优化与运行模式边界

本文记录 2026-10-29 的优化。后续启停、异常关闭、钱包取消和历史分批保护见 [2026-10-30 修复](EGM_FIXES_20261030.md)，当前发布与服务器状态以 HANDOFF 为准。

本轮应用代码为 `2f6d6f6`，已归入唯一当前入口 `main`；原工作分支已移除，固定基准及维护规则见 [版本维护](VERSIONS.md)。优化不检测服务器型号、CPU 数或内存，不减少市场、价格精度、历史、策略判断或成交检查，也不改变扫描、订单和持仓维护频率。换服务器后沿用同一实现。

## 共享外部观察，隔离账户结果

- 保留同一个公共行情源。相同 TEST 消息只解码一次，仍由原有 `MarketService.message` 应用盘口、价格步长、恢复事件和原生引擎消息；策略、风控、退出及赎回业务仍使用原实现。LIVE 不进入 TEST 解码分支。
- TEST 经共享查询入口对同一公开市场详情或盘口的**正在进行中**的相同查询合并请求；每个等待账户得到独立 JSON 副本。异常市场的缺失盘口证明仍按账户独立复核（通常每 token 300 秒），该路径尚未合并。请求完成即移除，不缓存已完成行情，不改变重试规则。取消一个账户不取消其他等待者；最后等待者退出时完成取消清理。
- 各账本保留自己的市场快照。只有完整、深度不可变的 Token 元数据可弱引用复用；资金、策略状态、盘口消耗、订单和持仓绝不进入共享缓存。缓存达到容量后直接完整解码，容量不是市场数或历史数上限。弱引用回调允许 GC 重入，不阻塞事件循环。
- 周期、目标、赎回集合均为空且没有在途订单的暂停账户，可跳过已经证明无工作的控制轮；保留已完成赎回历史时仍保守走原扫描，未将此规模优化加入当前修复。本地或外部 SQLite 写入、事务、代次改变或不确定状态立即使用原路径。已有持仓的退出及结算照旧。
- TEST 摘要页不构造没有返回给页面的市场明细；显示的资金仍实时从本账户计算。正常关闭和重置释放本账户原生引擎、订阅、缓存和数据库，不改 LIVE 关闭顺序。

## TEST 与 LIVE 互斥

暂停 TEST 仍然维护原有持仓的卖出和赎回，因此 PAUSED 不等于 TEST 后台完全停止。

显式启用 LIVE 时，要求所有可用 TEST 已经 PAUSED，然后停止并等待全部 TEST 行情、扫描、结算和采样任务退出。在进入任何 LIVE 私有客户端激活前，将运行模式意图原子保存到 `PM_DATA_DIR/execution-mode.json`。切换期间旧 START 和新操作均被拒绝。

LIVE 模式意图会跨重启保留；重启仍不自动解锁钱包、启用 LIVE 或启动买入，同时 TEST 后台保持停止。若需回到 TEST，页面复用运行按钮提供“恢复TEST后台（保持暂停）”，只在后端确认没有 LIVE 活动且允许恢复时可用。恢复先持久化 TEST 意图，恢复行情和维护后十个账户仍 PAUSED，需分别明确 START。

启用失败时先等待 LIVE 私有客户端完成清理；只有清理和模式保存均得到确认、且此前 TEST 后台原本启用时，才恢复暂停账户的后台维护。此前已停止、清理未确认、模式写入未确认或程序正在关闭时，保持停止并明确报错。不会故障后自动恢复交易。

`PM_LIVE_ENABLED=true` 的原部署方式也仅运行 LIVE 后台。LIVE 账本、钱包、签名、真实委托和赎回执行实现不进入 TEST 缓存；模式协调层增加的是互斥保护。

## 单账户故障

TEST 初始化、诊断、原生检查点和公共行情消费者的账户局部错误，只标记并暂停或隔离相关账户，不暂停正常兄弟账户。包括 1 号初始化失败时，已经建立的 2—10 号仍独立加载；不会拿不完整的 1 号配置新建其他账户。

公开元数据的可选清理逐账户处理，单账户清理失败会显示账户错误，其他账户继续清理及交易。共享磁盘保护、公共断网、进程退出或整机故障仍属于共享条件，不能通过同一进程内的数据隔离消除。

健康接口用 `accountErrors` 标出 TEST 局部错误；部分账户故障为 HTTP 200 / attention，全部 TEST 不可用、模式状态未确认、共享存储或 LIVE 后台失败仍为 HTTP 503。严格部署验收额外要求全部十个账户可用且没有任何错误，不会把部分可用当作全部通过。

## 验证口径

最终本地验收：1,221 项 Python 回归、114 项页面回归全部通过，Ruff 检查及格式检查通过。使用独立载入的 `e7ccb64` 行情和 TEST 实现，对 64／642／1,284 个市场及 1／2／10 个运行账户交叉进行 9 组对照，每组 600 条报价，受控财务状态差异均为 0。

回归覆盖十账户独立交易、公共请求合并及取消、旧代码结果对照、缓存满回退、外部数据库写入、关闭释放、单账户故障、模式切换取消与持久化失败、重启保持暂停、恢复后台不 START，以及前端账户和响应身份隔离。受控 LIVE 使用测试执行客户端，不会操作真实资金。

在固定 642 个订阅、600 条报价、10 个 TEST 加受控 LIVE 的重复基准中，报价处理 CPU 中位数从 0.188825 秒降至 0.086928 秒，约减少 54%。这仅代表该阶段，不能当作整台服务器降幅或十账户最大容量保证。独立载入旧版本行情实现的多组对照中，受控财务状态没有差异。

十份、每份 25,016 条的合成长元数据解码基准，启动 CPU 从约 4.74 秒降至 1.29 秒，Python 峰值分配从约 591 MiB 降至 341 MiB；达到缓存预算仍完整返回全部条目。实际进程内存及 CPU 还取决于持仓、交易和市场数量。

TEST 模拟成交与 LIVE 使用同一策略判断，但无法完全复现实盘网络延迟、排队成交、滑点及链上执行。TEST、CI 和部署验收通过仍不能代替真实资金买卖及正额赎回闭环验收。
