## 修复范围

- LIVE START 从 API 首次等待前绑定 runtime、账本代次和启动代次，在钱包锁与就绪检查后重新检查；底层启动在磁盘等待前记录启动代次。后续 PAUSE 使较早 START 失效，用户仍可再次明确 START。
- LIVE 关闭先阻止新买。暂停、前段排空或断连失败不会跳过其余私有任务及原生命令/事件队列收尾；调用者反复取消仍等待实际清理结束。账本及进程所有权覆盖最终回调，原始错误继续报告。
- 钱包导入准备阶段取消等待当前只读线程完成，然后停止后续阶段。文件发布开始后，取消仍等待写入、账本身份绑定、内存状态及检查收尾，再释放钱包锁。原有原子拒绝覆盖、绑定失败后显式解锁核对的恢复行为保留。
- 交易记录普通页与变化增量独立分批，每批最多覆盖 100 个 Fill 事件；同订单多次成交可跨批重复更新。页面每次轮询只读取一批，续批显示“同步中”，整轮完成后才推进确认水位。

策略判断、目标价及 tick、费用、份额、成交模拟、成本/PnL、止损及赎回金额规则保持原实现。没有新增持久财务主账本、数据库迁移或服务器规格分支，没有降低行情、扫描或交易维护频率。十个 TEST 的资金、盘口消费、参数、订单及历史继续独立；LIVE 启用和资金操作仍需用户明确执行。

## 历史接口与兼容性

`GET /api/{mode}/trade-records?paged=true` 保留普通 `limit`、`cursor`、`since`。新版页面另发送 `changes_paged=true`，存在续页时将 `nextChangesCursor` 原样带入 `changes_cursor`，同时保留整轮原始 `since`。

- `records`：首次成交序号排序的普通记录页；续批的首屏不会插入固定变化水位之后的新订单。行内累计数据仍由当前完整投影计算，固定的是变化覆盖区间，不是历史时点资金快照。
- `changes`：本批覆盖的订单变化，每批最多 100 个 Fill，订单 ID 在批内去重；不截断需要确认的成交。
- `changesHead`：本轮固定目标水位。读取期间新产生的 Fill 留待下一轮覆盖。
- `nextChangesCursor`：未读完时的续传位置，含账户账本代次、原始 since、目标及已覆盖序号；代次、范围或原始 since 不符时拒绝。
- `head`：当前已完整覆盖的变化前缀。旧页面按它逐批追赶；新版页面整轮完成后确认 changesHead。旧页面默认首屏也限制在已确认前缀，避免抬高插入门槛而跳过中间订单。

长期离线后的多批增量若涉及热缓存外记录，会在构造冷历史投影之前使该增量游标失效。新旧页面均重新读取最新页并重建“加载更多”入口，防止每批反复重放全部日志。之前展开的旧页需重新翻看；全部原始记录仍在账本中。小批冷旧订单迟到成交继续精确更新，普通深分页仍可读取所有历史，其原有重放成本未在本轮重构。

TEST 历史读取已有账户操作的取消所有权保护；独立 LIVE 历史读取的线程取消加固属于另行排期的只读资源优化，本轮未将它误报成 TEST 取消缺陷。
