# TEST 多账户边界修复（2026-10-28）

本次修复此前兼容性审计发现的启停并发、预评估、退出清理、初始化失败、重复行情规划及前端响应身份问题。没有修改 `rules.py`、`strategy.py`、`native.py`、`live.py`、`market.py`、订单签名规则或赎回执行模块；这些核心文件与单账户基线 `4de107a` 相同。

| 问题 | 修复与验证 |
| --- | --- |
| 排队 START 覆盖较晚 PAUSE，或跨越 RESET | 绑定运行实例、账本 generation 和启停 epoch；过期请求返回错误并保持暂停。真实 API 并发回归覆盖两种次序。 |
| 页面预评估消耗交易 dirty；快速重启复用旧候选排序 | 页面使用独立 pending 集合；有效 START 强制完整刷新。覆盖 1/10 号、摘要/市场/参数读取、有限资金排序及已消耗盘口。 |
| TEST 核对阻塞服务关闭，LIVE 清理被延后 | 关闭标记使在途 START 失效；先暂停并清理 LIVE，再等 TEST 核对结束。保留私有回调排空期间数据库可用的原有次序。 |
| TEST 部分构造失败后遗留 SQLite 或 Native 引擎 | 构造前保留失败对象所有权，逐一停止及释放组件；SQLite 初始化异常关闭连接。LIVE 仍使用原 Runtime 构造路径。 |
| 混合 LIVE 时十个 TEST 重复完整订阅规划 | TEST 专用请求入口共享原锁，仅完整就绪且严格状态签名相同时复用。LIVE 自己和通用控制入口始终完整规划；元数据、tick、恢复及缺盘口回归验证立即失效。 |
| 旧服务缺少账户身份，页面继续允许 2—10 号操作 | 清空视图并禁用操作，提示刷新；保留仅 1 号的旧协议兼容。迟到响应不能封锁新账户或 LIVE 视图。 |
| 保存中的旧响应覆盖继续编辑的新草稿 | 保存请求记录草稿代次；保留后续输入，并明确提示尚未保存。TEST/LIVE 页面均验证。 |

本地全量验证：1047 项 Python 测试、103 项页面脚本测试通过；格式和静态检查通过。隔离真实浏览器验证了 10 号独立改本金后，1 号本金仍为原值，LIVE 仍锁定且无 TEST 账户选择器。所有测试使用临时账本和受控 LIVE 传输，不接触真实钱包。

固定行情对照：10 个同时运行的不同参数账户、240 条公开行情、2400 次逐账户状态比较、3 次断流恢复，资金、订单、持仓等语义状态与原 Runtime 无差异，共生成 98 笔订单。此验证不等于所有行情情形或实盘闭环均已覆盖。

混合负载验证：642 个公共 token、每侧 20 档、600 条行情，注册未激活且未注资的原 LIVE 实例。12 轮中 120 次重复 TEST 规划被合并，12 次 LIVE 完整规划保留；测量阶段 LIVE 没有激活、签名、提交、撤单或账本写入。十账户独立行情处理仍比一个账户消耗更多 CPU；共享进程、内存、磁盘和网络，不能承诺对 LIVE 的物理性能零影响。

目标卖价沿用 `max(实际买入价＋加价, 实际买入价×倍数)` 后按市场价格步长向上取整的原规则。3¢、加价 1¢、倍数 1.67、步长 1¢ 时目标为 6¢，而不是不可挂单的 5.01¢。新增回归覆盖不同价格步长；不改历史持仓已保存的目标价。

服务重启仍默认暂停；本次不加入故障后自动恢复。发布时需一致性备份全部十个 TEST 账本和 LIVE，核对历史前缀、参数、generation、钱包与配置，验收后仅恢复发布前已运行的 TEST 账户。LIVE 地区限制、资金/手续费条件、真实买卖及正额赎回仍需独立验证，不能据此认定实盘就绪。
