## 页面如何解释这类持仓

平台可以将市场归档、停止接单或撤掉订单簿。此时程序仍持有原来的仓位和权利，但没有可执行报价。页面将它单独标为“市场已归档／停用，报价不可用，处置安排待核查”，显示本进程首次核实的时间；这个时间不是平台实际停用时间。

本次 17:14:13 CST 部署后采样的“持仓 92”是总数量，其中 1 笔已确认归档、报价不可用，其他未就绪持仓为 0；其余订阅为 4/4 组 READY、767/767 盘口完整。05:20 UTC（13:20 CST）的升级前诊断也曾确认 1 笔，但这两个计数只代表各自采样时间，不能作为将来状态。已确认停用的市场与普通断线、盘口暂未完整、暂无买盘分开显示。正常市场继续运行；停用持仓保留独立提醒和未估值数量。市场重新开放也必须先取得新的完整盘口，才能恢复交易。

官方对 `archived` 的解释是市场进入只读状态，不再交易或更新结算信息。因此，归档不能被当作“等待一会就一定恢复或结算”。需要核实官方是否有取消、迁移或结算安排；程序不会凭标题将旧仓映射到同名新市场。[官方市场状态说明](https://docs.polymarket.com/market-data/market-details)

## 确认停用与复查

- 核对 Market ID、Condition ID、两个 Token 及其结果标签；不接受不同身份、未知协议或不完整、矛盾的状态。
- 归档需 `archived=true`、`active=false`、`acceptingOrders=false`；其他停单情况需要多个明确一致的停止标志。
- 还须同一 Token 的官方 `/book` 返回 HTTP 404 且错误明确为订单簿不存在。单次 404、403、超时或缺失字段都不足以认定市场停用。
- 确认后，隔离同一 Market/Condition 的已知结果订阅与交易入口，保留持仓监控身份、原生工具、订单、TEST 已消耗深度和私有对账；同 Event 的其他市场不受此分类影响。
- 停用市场至少间隔 300 秒复查；额外缓存市场每轮最多检查 16 个，沿用最多四个并行查询。网络或格式失败保留已确认的保护状态，并记录本次核对失败。

复查是观察机制，不保证平台最终提供交易、结果或回款。重新开放须身份一致且交易标志完整恢复；所有受影响结果先失去旧盘口有效性，再恢复订阅。新完整快照到来前，买卖提交仍受保护。共享源若 30 秒仍未给恢复中的结果提供新快照，只对该 Token 做退订／重订阅，并使使用该 Token 的消费者重新建立基线；其他 Token 的连接与行情继续使用。恢复路径保留已知时间下限，旧快照不能重新制造可成交深度。

## 估值与资金

任一正数量未结算持仓无法报价时，完整持仓价值、总资产和未实现盈亏继续显示未知。页面另外展示“可估值持仓小计”，并明确它不等于全部资产；可用现金、已实现盈亏、未估值数量分别保留。统计包含未展开或翻页外的全部仓位。

停用状态不改变持仓数量、成本、目标、冻结预算、原生成交、收益历史或待处理的资产权利。正式结果仍需原有严格身份、状态和 payout 核对；LIVE 回款仍需链上与账户确认，不能根据“归档”或“没有盘口”推断为零、退款或已赎回。[官方结算机制](https://docs.polymarket.com/concepts/resolution)

START 和其他市场的运行方式保持原规则。提交前在同步入口以及 LIVE 签名后、等待连接资源后、每次 HTTP POST／重试边界检查受影响市场。确定尚未 POST 的延期只结束该订单，保留账户就绪及其他市场的卖出；一旦请求可能发出，原有未知结果、资金／份额占用及恢复隔离不变。已确认权利的独立结算路径不依赖公开盘口可用性。

## 可观测性与验证

`/api/health` 的 `marketData` 按已启用模式提供聚合计数：停用持仓、其他未就绪持仓、连接组及盘口完整数量。停用持仓使用非致命 `attention`，行情恢复使用 `recovering`；进程健康与全部资产可估值是两个维度。公开健康接口不包含持仓 Token、市场标题、钱包资料、数量或资产金额。页面和认证 dashboard 提供具体持仓原因。

可用性与恢复标记只在内存中观察，不改变数据库格式；重启后重新核实平台状态。本地 880 项 Python、37 项页面测试、Ruff 检查／格式（105 文件）及 JS/shell 语法通过。回归覆盖严格停用证明、普通网络故障、单市场隔离、同市场双结果、共享消费者、静默及旧快照恢复、TEST 深度、隐藏仓位估值、公开接口隐私、排队 BUY/SELL 及可能 POST 的未知结果。压力与交易边界使用受控接口和真实 Runtime；没有实际 LIVE 交易或链上资金操作。
