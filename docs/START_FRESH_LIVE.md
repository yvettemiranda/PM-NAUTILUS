## 你需要准备什么

**先确认账户可用，再准备资金。**本程序当前完整路径仅支持普通 EOA（签名类型 0）和单签 Safe（类型 2、唯一 owner、阈值 1）。[官方钱包流程](https://docs.polymarket.com/trading/wallets-auth#set-up-eoa-trading)要求 EOA 列入允许交易名单（allowlisted）；这项资格尚未验证，不能先给未知资格的 EOA 充值再假定能交易。新建 Polymarket 官方账号默认使用 Deposit Wallet（类型 3），当前不支持；不要把其资金地址当作普通 EOA 或改签名类型强行接入。新钱包与新服务器本身不保证可以实盘。

- 一台允许 Polymarket API 新开仓的服务器。初次安装仍需请 Codex 或管理员配置 Docker、网页 HTTPS 和登录密码；完成后，日常钱包操作在程序网页的 **LIVE** 页进行，不必每次进服务器。
- 自己签名钱包的 **12 个助记词或私钥**。已有平台账户的资金 Safe 可能不是这个密钥派生的 EOA。资金地址可留空查找已有 Safe，或明确填 Polymarket 显示的**公开资金钱包地址**；保存后须亲自核对签名地址与平台资金地址。若是别的助记词长度、硬件钱包或不支持的钱包类型，先不要尝试导入。
- 确认类型与官方资格后，准备资金账户中的交易资金 **pUSD**，以及签名账户在 **Polygon 主网**的手续费币 **POL**。pUSD 按已保存的策略金额核对，POL 按实际链上手续费核对；单签 Safe 也需由签名 owner 持有 POL。
- 一个你能长期保存的**解锁密码**，至少 12 个字符。它用于解锁服务器上的加密钱包文件，和网页登录密码是两回事。丢失后程序无法替你找回钱包秘密；还需要保管好钱包原有恢复方式。

不要把助记词、私钥、解锁密码发到聊天、GitHub、截图或普通笔记。输入位置只有你通过 **HTTPS 打开的本程序 LIVE 钱包页面**。这套方式会把你输入的助记词或私钥经 HTTPS 交给服务器处理：助记词只用来派生签名密钥，磁盘只保存加密钱包文件；LIVE 解锁后，服务器进程在内存中持有签名密钥以便交易。网页方案并不意味着密钥永远只留在你的电脑。

## 首次实盘操作顺序

1. **请人完成一次服务器安装。**让 Codex 或管理员从 [GitHub 仓库](https://github.com/yvettemiranda/PM-NAUTILUS)取得经验证的版本，按[部署手册](DEPLOY.md)配置 Docker、HTTPS 与网页登录，并从新服务器实际出口核对地区。安装者先确认公开的 [交易规则文件](../config/strategy-profile.json) 仍是你要用的版本，并在首次启动前先把规则应用到空白 TEST 1、LIVE 两份账本；首次启动再由 TEST 1 初始化 2—10 号空白模拟账户。安装完成应先显示 `TEST / PAUSED`，LIVE 钱包未接入。
2. **打开网页，先看规则。**登录后可继续使用 TEST；切到 LIVE 只是查看实盘页，不会下单。点击右上角齿轮，网页会展开并定位到交易设置；在 LIVE 页核对每轮金额、筛选、目标卖出和止损，和 TEST 分别核对。两套规则各自保存，TEST 中改动不会自动复制到 LIVE。沿用已有规则，不另加首轮总投入、单笔金额或试单次数限制。
3. **确认兼容与官方资格后，在 LIVE 页接钱包。**选择“12 词”或“私钥”，只在网页输入签名密钥并设置解锁密码。资金地址可留空查找已有单签 Safe；程序只读核对官方资料、派生地址和链上 owner/阈值，失败即拒绝，不猜测资金地址或创建新钱包。也可明填平台公开资金地址，仍按原方式核对。请比较网页显示的签名地址与平台资金地址，二者可能不同。钱包加密保存在 `/data/wallet/live.vault`，不会把助记词原文写入文件或把私钥、密码上传 GitHub；不能覆盖已有真实交易的账本。
   如果接错，且从未有任何 LIVE 交易、未启用、没有在途交易：打开“钱包备份与管理”，输入原解锁密码，确认“清除当前钱包”，再用同一密钥重新导入，资金地址留空或填写正确的平台地址。程序允许取消尚未形成待确认交易的规范准备或失败状态；未知提交、不可信状态、有交易历史仍拒绝，nonce 记录保留，不自动改绑旧钱包。完整检查边界见 [部署手册](DEPLOY.md#71-用户在网页上的顺序)。
4. **点击“检查账户”。**网页只读检查服务器地区、钱包类型、资金和手续费余额、交易所授权、标准与 Neg-Risk 的 CTF 赎回适配器授权、原有挂单与持仓，以及它是否与 LIVE 账本属于同一账户。实际份额用链上精确余额核对，API 显示的小数截断不会被当作缺仓；查询不完整或不一致仍会阻止启用。缺少交易授权时，按 [Polymarket 官方授权流程](https://docs.polymarket.com/trading/wallets-auth#set-up-trading-approvals)完成同一资金账户的 pUSD 和 CTF 交易权限，再回来检查；不需要为此先下试单。若缺少赎回授权，网页的“授权赎回”仅设置两个赎回适配器权限，会签署并广播真实 Polygon 交易、支付 gas，须由你决定是否执行，并等待确认后重新核对。签名账户 POL 须够支付当次手续费；补 gas 或完成赎回授权后，仍需处理其余检查项。已有授权通过时无需重复授权。程序外旧仓仍须核对，只有链上严格证明已结算且收益分子为零的标准二元残仓不阻止启用，无需付 gas 清理；正收益、未结算、未知或混合权利继续阻止。程序不会接管、烧毁或自动赎回这些旧仓；完整边界见 [实盘准备检查](LIVE_READINESS.md)。
5. **先暂停全部 TEST，再确认检查并决定是否启用和 START。**程序会拒绝仍有 TEST 运行的启用请求；全部 TEST 暂停后，等待其行情、扫描、结算和采样退出并保存 LIVE 意图，再激活 LIVE。启用后状态先是 `LIVE / PAUSED`；这时仍没有自动开始新买。再由你按 **▶ START**，程序才按现有规则发出真实交易。PAUSE 会停止新买；已有本程序持仓的卖出、止损和结算仍可能继续。首次真实交易及结算尚未在正式钱包完成全链路验收。

服务器重启不自动恢复 RUNNING。保存为 LIVE 的目录仍保持 TEST 后台停止；需要继续 LIVE 时，在 LIVE 页解锁、重新核对并明确启用。**LIVE 未解锁期间，本程序不会管理已有 LIVE 持仓。**不能把暂时没有显示的持仓理解为已清仓。若改回 TEST，确认 LIVE 没有活动且后端允许，再明确“恢复TEST后台（保持暂停）”；十个 TEST 仍为 PAUSED，之后分别 START。切换页面只改变查看对象。

**地区核对：**2026-10-07 22:47 CST 的硅谷服务器出口查询为 `blocked=true`、`US/CA`；2026-10-14 本轮升级前的账户检查仍显示当前服务器出口不允许 API 下单。各次结果仅代表对应采样，最新状态以交接记录为准。启用前必须在拟使用的服务器上点击“检查账户”，从它自己的网络出口取得最新结果；地区检查不通过则不能启用。不能仅凭服务器名称或购买地点判断资格。

## GitHub 能恢复什么

GitHub 有程序、说明和你同意公开的 `config/strategy-profile.json`。它**没有**服务器钱包、解锁密码、真实交易记录或最新账本。公开规则文件也不会随着你在网页改参数而自动更新；以后换服务器前要确认它仍是你想用的规则。

全部十个 TEST 的模拟历史是否保留由你明确决定，不能只迁移 1 号而无意漏掉 2—10 号。**第一次实盘以后，LIVE 账本就不能随便丢。**它记录程序自己的订单、持仓和待结算权利；只下载 GitHub 后从空白 LIVE 启动，程序无法可靠识别这些历史。LIVE 页的 `.pmnb` 是下载时的加密快照，可作日常备份，但当前程序在 PAUSE 后仍可能继续卖出或赎回，所以它不能自动作为最后一份迁移备份。换服务器时由管理员停止旧实例、制作最终一致性加密备份，再在新服务器恢复并核对；不能让两台服务器同时管理同一钱包。已开始的恢复会先完成钱包和账本写入再释放操作锁；取消网页请求不等于停止后台恢复，应重新查看钱包状态。备份和恢复细节见[部署手册](DEPLOY.md)。
