- 十账户参数、资金、订单、持仓、模拟盘口消耗、记录、曲线和操作身份隔离；1 号原账本及既有历史保留；快速切换和迟到响应不串账户。
- START／PAUSE／RESET 并发、旧请求代次失效、完整候选重新评估；页面预评估不消耗交易工作。
- 公开请求仅合并进行中的相同 TEST 请求，不缓存完成结果；每个等待者独立 JSON，失败、取消、最后等待者退出及关闭清理均有回归。
- 公共 Token 元数据的完整不可变性、弱引用释放、GC 重入、并发、预算满回退和 LIVE 原解码路径。
- 暂停且无业务工作的控制轮证明；外部 SQLite 写入、事务、代次变化或不确定状态恢复原路径。
- 单账户构造、检查点、诊断、订阅准备及元数据清理异常不暂停正常兄弟账户；全部不可用和共享故障仍按全局故障报告。
- LIVE 启用前全部 TEST 暂停、任务排空与模式意图持久化；切换取消、私有清理失败、写盘失败、重启锁定和明确恢复 TEST 后台但不 START。
- TEST 正常关闭与连续重置的原生资源释放；LIVE 清理顺序、真实执行器及钱包边界保持。
- 价格步长、目标价、含费预算、盘口预演、原生事件、账本一致性、退出及赎回原有规则回归。

所有私有执行和链上边界测试均使用临时账本、受控 LIVE 客户端及替身响应，不操作真实资金。

## 性能证据的适用范围

最终固定输入、十个 TEST、642 个订阅、600 条报价，另注册未激活、未注资的受控 LIVE；三次重复的报价阶段 CPU 中位数从 0.186748 秒降至 0.079258 秒，减少约 57.56%。没有真实 LIVE 激活、订单或测量阶段 LIVE 账本写入。混合消费者测试用于验证底层旁路，正式应用层已禁止两种后台同时运行。

十份各 25,016 条合成长元数据的解码基准，CPU 约 4.74 秒 → 1.29 秒，Python 峰值分配约 591 MiB → 341 MiB；超过缓存预算仍完整返回全部记录。具体内存和时间取决于数据形状。

服务器同样 1、2 号运行、其余暂停的两次五秒采样，应用 CPU 约 99.79% → 26.40%（以一个核心为 100%），容器内存约 1,008 MiB → 792 MiB。该快照受行情、进程重启和当时负载影响，不能当作长期容量、所有阶段降幅或十账户最大吞吐承诺。
