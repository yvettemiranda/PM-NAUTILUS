# TEST 多账户

TEST 支持固定的 1—10 号模拟账户。每个账户使用同一套策略和模拟成交规则，可分别设置参数和初始资金，并独立启动、暂停和重置。页面顶部的账户选择器只切换查看及操作的对象，不会启动或暂停任何账户；其他账户在后台继续运行。

## 账本与初始值

- 1 号继续使用原来的 `TEST/state.sqlite`，不搬迁、复制、清空或重置原账本。
- 2—10 号分别使用 `TEST/accounts/2/state.sqlite` 至 `TEST/accounts/10/state.sqlite`。
- 新账户首次建立时复制 1 号当时保存的策略参数和初始资金设置，不复制余额、持仓、订单、成交、收益曲线或交易历史。首次建立后，各账户参数不再互相同步。
- 每个账户分别保存订单、成交、持仓、收益采样、策略状态及模拟盘口消耗。市场元数据在各账本中保留所需快照，保证历史展示与重放。
- 所有路径均相对于 `PM_DATA_DIR`，位于现有持久化数据卷内。

公共市场发现和行情连接由 `PublicMarketHub` 共享。程序从 Polymarket Gamma 官方接口分页读取市场目录，从 CLOB WebSocket 订阅各账户所需盘口的并集。每个账户使用自己的模拟盘口与消耗记录，一个账户成交不会占用另一个账户的模拟流动性。

各账户可以单独开启市场扩展、按市场开仓和最优卖档买入。共享扫描按各账户的设置分发市场。用账户自己的 `state.sqlite` 可以分析成交、持有和手续费。见 [可选策略与账本分析](STRATEGY_PREFERENCES.md)。

暂停账户仅接收已有持仓或订单所需的盘口，点击 START 后恢复完整候选订阅，按最新完整盘口和原有排序判断买入。已有持仓的卖出、止损、订单维护和结算沿用原调度。

盘口和连接完整、所有消费者的订阅及控制状态完全未变时，共享行情源可以跳过 TEST 发起的重复订阅规划。LIVE 独立运行时及通用控制入口发起的同步仍走原有完整规划；新增订阅、重置、缺盘口、恢复请求或其他不确定状态立即使用原有完整同步路径。底层混合消费者仅用于兼容性回归，正式应用不允许 TEST／LIVE 后台同时运行。LIVE 的运行实例、成交规则、心跳参数及钱包逻辑保持原样。

## 启停、资金与重置

启用单账户模式前，先暂停将被设为只读的账户。在 `.env` 设置 `PM_TEST_ACTIVE_ACCOUNT=1` 后，只有 1 号账户可手动启动、修改设置和重置。也可指定 2–10 中的一个账户。清空此变量可恢复十账户模式。

Docker 部署修改 `.env` 后需按部署流程重新创建应用容器，才能应用新的环境变量。`docker compose restart` 会沿用原容器环境。直接运行程序时，把该变量传给新启动的进程。 [部署手册](DEPLOY.md#2-日常更新一键部署) · [Docker Compose 文档](https://docs.docker.com/reference/cli/docker/compose/restart/)

其余账户的设置、成交记录和收益曲线仍可查看。程序会只读核对账本，确认没有持仓、待处理订单、未结束的结算或未恢复的记录后，才跳过该账户的交易引擎、行情和收益采样。需要处理已有事项的账户继续按暂停规则维护。尚未建立的其他账户在此模式下保持未初始化。

单账户模式下，健康接口的 `availableTestAccountCount` 包含可访问的只读账户。`activeTestAccountId` 是可启动的账户，`loadedTestAccountCount` 是已加载的引擎数，`coldTestAccountIds` 是无需后台维护的账户。网页查看其他账户时会标明只读。

进程重启后，既有账本的参数与历史保留，加载的 TEST 账户以 PAUSED 启动。运行模式为 TEST 时恢复 TEST 后台。若保存为 LIVE，TEST 行情、扫描、结算和采样均保持停止，LIVE 钱包保持锁定且 LIVE 保持停用。确认没有 LIVE 活动且后端允许时，可明确“恢复TEST后台（保持暂停）”，随后再启动需要运行的账户。单账户模式只允许启动选定账户。PAUSE 停止新买并取消未完成买单，已有持仓的目标卖出、止损和结算仍继续处理。

排队及核对中的 START 绑定发起时的运行实例、账本代次和启停代次；后来的 PAUSE、RESET 或服务关闭会使其失效。每次有效 START 都用完整最新候选排序重新判断，查看市场页面不能消耗待处理的交易工作。关闭服务先暂停交易并完成 LIVE 清理，再等待 TEST 核对结束；失败的 TEST 初始化会明确释放已创建的引擎和数据库资源。

初始资金只在该账户暂停且没有交易历史时可修改。已有历史若需要重新设置本金，应先明确执行该账户的重置；重置会清空该账户的模拟历史并恢复原有默认设置，其他账户不受影响。重置保留双重确认，确认文字明确标注账户号。

## API 兼容

现有 TEST 接口使用 `account_id=1` 至 `account_id=10` 指定账户。省略时固定指向 1 号，保持原有脚本兼容。单账户模式选用 2–10 号时，启动、修改设置、重置或恢复 TEST 后台的请求需要显式填写该账户号。账户号通过整数白名单解析，不接受数据库路径。

账户参数适用于 dashboard、preferences、start、pause、reset、trade-records、validation 和 performance。显式恢复使用 `POST /api/TEST/restore-background?account_id=N` 和 `{"confirmation":"RESTORE TEST"}`，也校验当前账户可用性；它只恢复模式后台，不启动任一账户，且必须由后端明确允许。账户选择只存在于浏览器中，服务端没有全局“当前账户”；不同浏览器或标签页可查看不同账户。前端将请求与发起时的模式、账户和视图代次绑定，迟到响应不能覆盖另一个账户；记录游标、持仓快照和曲线也分别隔离。

LIVE 继续使用 `LIVE/state.sqlite` 和原有钱包、账本及交易执行实现。TEST 账户参数不进入 LIVE 钱包接口或执行逻辑。TEST 与 LIVE 后台互斥，启用 LIVE 前需先暂停所有 TEST；具体切换、重启和显式恢复行为见[通用优化与运行模式边界](archive/TEST_OPTIMIZATION_20261029.md)。

页面发现响应的账户或模式不符时，清空当前展示并禁止交易操作，要求刷新；旧版单账户服务仅兼容 1 号，不能在缺少账户身份的响应下操作 2—10 号。保存参数时继续编辑的新草稿会保留，不被较早保存请求的返回值覆盖。

## 目标卖价与价格步长

目标卖价沿用原规则：先取「实际买入价＋加价」与「实际买入价×倍数」中较高者，再向上对齐到市场允许的最小价格步长，并保留原有 99¢ 上限。它不是简单保留两位小数。

例如实际成交 3¢、加价 1¢、倍数 1.67，计算结果是 `max(4¢, 5.01¢) = 5.01¢`。若市场步长是 1¢，合法目标价为 6¢；步长为 0.1¢ 时为 5.1¢，步长为 0.01¢ 时才是 5.01¢。买入成交时保存该笔的目标价；之后修改参数不重算已有持仓的目标。多账户版本没有修改此公式或重写历史目标价。

## 运维与验收

后台健康检查按账户标注状态和错误来源，原有默认 TEST 状态字段继续代表 1 号。元数据维护分别使用各账户自己的业务引用与清理游标。磁盘保护仍是整个数据目录的统一保护，不自动删除模拟账本、交易历史或钱包。

账户的资金、订单、策略状态和操作相互独立，服务器进程、CPU、内存、磁盘和公共行情源仍然共享。公共断网、进程退出、磁盘不足会影响多个账户。单账户模式验收应检查选定账户能正常启停，其他账户可只读查看，并核对有待处理事项的账户仍在后台维护。十账户模式验收应检查多账户同时消费行情时的网页响应，以及启停、改参数、成交和重置的账户隔离。

升级前后应核对全部既有 TEST 和 LIVE 账本的代次、参数和历史，单账户模式下尚未初始化的账户可继续保持未初始化。确认快速切换账户时数据仍对应各自账户，重启后加载的 TEST 账户均暂停。数据备份应使用一致性 SQLite 备份或停止写入后的完整快照，同时保全 WAL 中的数据。
