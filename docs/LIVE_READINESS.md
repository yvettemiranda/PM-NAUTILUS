## 网页流程（2026-10-14 文档核对）

首次安装服务器、HTTPS 和网页登录后，钱包操作在同一个网页的 **LIVE** 页完成；TEST 不要求钱包。用户可输入 12 词 BIP39 助记词或私钥、Polymarket 显示的公开资金地址，以及单独设置的解锁密码。程序由输入派生签名地址并要求核对钱包归属；助记词原文不落盘，加密文件位于持久数据卷 `/data/wallet/live.vault`，解锁后服务器进程内存中持有签名密钥。输入经 HTTPS 到达服务器，因此只能在自己确认的本程序 HTTPS 页面输入；不要把秘密发到聊天、GitHub 或截图。当前实现只支持普通 EOA，以及 owner 唯一、阈值为 1 的 Safe。

资金地址可留空，只读查询官方 Gamma profile 并核对 factory 派生、已部署 Safe、唯一 owner 与阈值 1。自动发现仅用于已有单签 Safe，资料缺失、不支持或查询异常拒绝，不回退猜测 EOA；明确填写地址仍按原语义核对。已保存钱包不自动改绑；未有任何 LIVE 交易、未启用且无在途时，由用户用密码明确清除空白钱包后重新导入。规范 ACTIVE/pending=None 的未签名准备及合法 FAILED/prepare 可清理，nonce 下限保留；未知或不可信状态拒绝。该流程已部署，本轮由用户重新导入后已只读核对正确 Safe 及账本绑定。

完整路径的签名类型分别为 EOA(0) 与单签 Safe(2)。[官方 EOA 准入说明](https://docs.polymarket.com/trading/wallets-auth#set-up-eoa-trading)要求允许交易名单资格，本程序尚未验证此项；新建官方账户默认的 Deposit Wallet(3) 当前不支持。先核实类型与官方资格，再准备资金，不能仅依据本地钱包类型检查或余额授权结果认定 EOA 已获准交易。

网页“检查账户”包含账户认证、pUSD/POL 余额、交易授权、标准与 Neg-Risk 的 CTF 赎回适配器授权、全部开放挂单、实际钱包持仓和服务器出口地区。持仓 API 保持 OPEN、零过滤下限及全分页，完整结果只用于发现 token；本程序份额使用本次新取固定区块的 CTF 六位原子余额与账本精确核对，不把 API 截断的四位显示数量当作实际数量。正数量权利即使 API 没有显示行也查询；历史已知零数量 token 保留自有身份，若 API 出现该 token，仍须核对链上零余额。查询失败、缺字段或结果不一致均不放行。

**程序外旧仓的处理边界：**一般外部持仓仍阻止启用。唯一可忽略的是链上严格证明已结算、收益分子为零的标准二元 CTF 输方残仓：官方 pUSD/USDC.e 抵押资产、空父集合、Condition/结果索引/两个 token 的派生身份须一致，分子之和等于正分母，另一结果余额为零。显示价格、`redeemable` 和舍入金额不作证明；极小正收益、未结算、Neg-Risk、未知身份或 RPC 失败继续阻止或 UNKNOWN。这不适用于本程序已知 token，不接管、不烧毁、不赎回这些外部残仓，也不修改账本。严格零收益旧仓无需为了接入程序另付 gas 清理。

资金账户需有覆盖已保存每轮金额的 pUSD；签名账户需有支付 Polygon 链上手续费的 POL。两者用途不同，pUSD 不能直接支付 gas；单签 Safe 的本程序交易由 owner 发送，POL 也应在签名 owner 地址。POL 有余额不保证足够，实际授权仍须按当次估算手续费核对。

检查本身不会下单、取消订单或自动授权。缺少 pUSD 或 CTF 交易所授权时，按 [Polymarket 官方交易授权流程](https://docs.polymarket.com/trading/wallets-auth#set-up-trading-approvals)处理同一资金账户，再回本程序重新检查；不要为触发授权先下试单。网页“授权赎回”仅设置标准与 Neg-Risk 的 CTF 赎回适配器权限，不代替交易所授权；用户确认后会签署并广播真实 Polygon 交易、支付 gas，须等授权核对通过。全部检查通过后，用户确认启用，程序进入 **LIVE / PAUSED**；只有另行点击 **▶ START** 才允许新买。启用失败或取消时会完成资源清理，完成启用前网页仍显示未启用。启用后的 PAUSED 仍可能维护已有真实仓位，不能当成只读模式。

授权或赎回结果未明时保留账户原交易的 raw/hash/nonce，不能让另一项事务复用；关闭网页或取消请求不会撤销已经开始的线程或链上交易。后台工作结束前保持操作锁，存在待确认授权时不能删除钱包或恢复覆盖。先刷新并检查原结果，再执行后续操作。

应用重启后，网页钱包保持锁定；须重新输入解锁密码、核对并启用，不自动恢复 RUNNING。网页可下载包含加密钱包及同一时点 LIVE 账本的 `.pmnb` 加密备份，并在空白 LIVE 账本的新服务器恢复。已部署版本采用分块压缩、加密和流式上传，上限为 4 GiB 原始 LIVE 数据库、2 GiB 加密包。恢复请求被取消时，程序仍保持钱包操作锁及上传文件，等待后台恢复完成后才释放；取消页面请求不等于终止已经开始的恢复。

备份是时间点快照；PAUSE 后卖出和赎回仍可能写账，已有真实 LIVE 记录的最终换服备份须由管理员停止旧实例后制作。备份文件和密码应分开保管；GitHub 只有源码、说明和公开规则，没有钱包或真实交易记录。新旧服务器不能同时管理同一钱包。操作顺序见 [从 GitHub 到首次实盘](START_FRESH_LIVE.md) 和 [部署与迁移手册](DEPLOY.md)。

## PAUSED 状态与原有命令行只读检查

`LIVE + PAUSED` **不等于只读模式**。按既定规则，PAUSE 停止新买，但已有仓位仍可卖出、止损和赎回；`app.py` 在 LIVE attach 时挂接 RedemptionService，且没有独立的“关闭自动赎回”配置。`auto_approve_redemption=false` 只关闭自动授权，不能阻止已授权仓位赎回。

原有 `pm_nautilus.preflight` 命令仍可供管理员独立检查公开链上状态；日常网页钱包流程由 LIVE 页面执行完整就绪核对。该命令不启动应用 LIVE runtime、不构造签名钱包、不导入私钥：

